# 웹 사무실 + PC 실행기 (v0.17)

## 바뀐 구조

기본 실행 화면에서 Streamlit을 제거했습니다. `start-office.bat`은 이제 `python -m office.web_server`를 실행합니다. 아바타·명령·대화·승인 화면은 `site/`의 일반 HTML/CSS/JavaScript이며 GitHub Pages와 PC에서 같은 파일을 사용합니다. 업무 저장·총괄 배정·Codex·분석·외부 작업은 기존 PC 실행기가 담당합니다.

기존 SQLite 업무 DB, 프로젝트, 자료, 승인, 예약과 실행 증거는 유지됩니다. Streamlit 파일은 이전 버전 호환용으로 남아 있지만 기본 실행기에서 불러오지 않습니다. 이 전환이 과거 Windows Codex 오류 267을 해결했다고 보장하지는 않습니다.

## 시작

1. 기존 사무실 터미널을 닫습니다.
2. `update-office.bat`을 실행합니다.
3. 브라우저에 PC 웹 사무실이 자동으로 열립니다. 시작 링크의 연결 코드는 주소 표시줄에서 즉시 제거되며 페이지 메모리에서만 사용합니다.
4. 출근 후 명령을 입력합니다. 화면 새로고침이 Python 업무를 다시 시작하지 않습니다. 명령은 고유 ID로 접수해 재전송에 따른 중복을 막습니다.
5. 대표 아바타 또는 검토함 버튼에서 실제 대상·변경 내용을 확인한 뒤 승인합니다.

기본 주소는 `http://127.0.0.1:8501`입니다. 예전 Streamlit이 켜져 있으면 포트가 겹치므로 먼저 종료합니다. 업무 지시·대화·프로젝트/자료 등록·연결 작업·브라우저 준비·예약·산출물 ZIP·원본 반영을 웹 화면에서 처리합니다.

## GitHub Pages에서 사용

PC 사무실의 **Pages 사무실 열기**를 누르면 같은 연결 정보로 Pages를 엽니다. 또는 Pages의 연결 화면에 PC 실행기 주소와 `%LOCALAPPDATA%/MyLittleOffice/web-connection.txt`의 연결 코드를 입력합니다. 연결 코드는 실행기를 다시 켤 때 바뀌고 GitHub에 업로드하지 않습니다. 페이지 새로고침 후에는 코드를 다시 입력해야 합니다.

HTTPS Pages에서 로컬 실행기에 접근할 때 브라우저가 로컬 네트워크 접근 허용을 요구하거나 연결을 차단할 수 있습니다. 브라우저가 허용하는 범위에서만 연결하며 보안 기능을 끄지 않습니다. 연결이 막히면 PC 주소로 **같은 웹 사무실**을 사용합니다. 로컬 화면은 Streamlit으로 돌아가는 것이 아닙니다.

PC API는 loopback에만 열리며 모든 업무 API에 연결 코드 인증이 필요합니다. Pages의 정확한 origin과 해당 PC origin만 허용합니다. 연결 코드는 해당 PC 업무를 제어할 권한이므로 외부에 공유하지 않습니다. Pages 공개 저장소로 업무 DB·비공개 대화·로그를 전송하지 않습니다.

휴대전화의 `127.0.0.1`은 PC가 아니므로 이 구성만으로 원격 접속되지 않습니다. 모바일 원격 실행용 인증 중계는 별도 범위입니다. PC를 꺼도 Pages 화면은 열리지만 실제 업무는 실행되지 않습니다.

## 검증 범위

HTTP 테스트에서 연결 코드, Origin 제한, Pages CORS/로컬 네트워크 preflight, 명령 중복 접수 방지, 대화와 승인 검증을 확인합니다. 별도 Chromium 통합 테스트에서 같은 웹 화면과 실제 PC API를 연결하여 출근→명령→대화→대표 검토→퇴근을 검사합니다. 이 테스트는 모의 업무 실행기를 쓰므로 사용자 Windows의 Codex·네이버 실게시 성공을 의미하지 않습니다.
