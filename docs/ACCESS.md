# 직원 실행·외부 자료 접근 (v0.11)

앱을 종료하고 `update-office.bat`으로 업데이트한 뒤 새 업무나 추가 지시를 접수합니다. 이미 끝난 업무의 실행 증거는 바꾸지 않습니다.

## 파일 제작과 검토

기획·사업개발, 개발, 디자인·콘텐츠, 마케팅·영업, 데이터·운영과 총괄 최종 검토는 선택한 프로젝트 작업 사본에 쓰기 권한을 갖습니다. 문서·샘플·판매 문안·코드를 실제 파일로 만들고 테스트·분석을 실행할 수 있습니다. 총괄의 첫 배정 단계는 JSON 계획을 만드는 단계로, 앱이 제공한 파일 목록·자료와 웹 조사로 배정하고 셸은 사용하지 않습니다.

제작 요청은 제안으로 끝내지 않고 실제 결과 파일과 완료 기준을 담당 업무에 포함하도록 지침을 보완했습니다. 제안·설명만 요청한 경우는 파일 제작을 강제하지 않습니다. 총괄은 자신의 현재 권한과 앞 직원 실행 증거의 권한을 구분해 검토합니다. 권한 허용과 작업 완료는 별개이므로 실제 변경·검증 증거를 확인해야 합니다.

## 공개 자료와 연결 계정

실시간 웹 검색을 활성화하고, 사용자 Codex 설정을 읽어 PC에 등록된 MCP·도구를 사용할 수 있게 했습니다. 공개 GitHub 원문과 웹 자료를 실제로 열어 확인하도록 지시합니다. GitHub CLI 로그인과 기존 `GH_TOKEN`·`GITHUB_TOKEN` 인증 환경도 직원 프로세스에 유지합니다. 비밀 값은 결과·대화·로그에 출력하지 않도록 지시하고 일반적인 키 패턴을 가립니다.

사용자가 외부 자료 접근을 요청했으므로 이번 버전 최초 시작 시 기존 등록 프로젝트의 네트워크를 한 번 활성화합니다. 새 프로젝트도 네트워크 사용이 기본 선택됩니다. 이후 프로젝트별 설정에서 네트워크를 끄면 재시작해도 다시 강제로 켜지 않습니다. 이 설정은 로컬 명령의 네트워크에 적용하며, 호스팅된 웹 검색과 MCP는 각 도구·계정 및 관리 정책의 제한도 받습니다.

**프로젝트·배포·홍보 연결 관리 → GitHub·연결 도구 상태 확인**에서 GitHub CLI 로그인 여부와 로컬 Codex의 활성 MCP 이름을 볼 수 있습니다. MCP 등록 목록은 연결·인증 성공을 보증하지 않으며 실제 호출 결과로 확인합니다. 도구 설정 원문이나 토큰은 상태 화면에 표시하지 않습니다.

ChatGPT 웹의 연결 계정이 로컬 Codex로 자동 이전되지는 않습니다. 비공개 저장소나 계정 전용 매체는 PC의 Codex에 MCP를 등록·인증하거나 해당 서비스 CLI로 로그인해야 합니다. GitHub CLI는 `gh auth login`, Codex 연결 도구는 `codex mcp list`로 확인합니다. 지원하지 않는 서비스가 자동으로 연결됐다고 보고하지 않습니다. 공개 게시·배포·홍보 발송은 사용자가 승인한 대상·내용·행위 범위에서 등록 작업 또는 사용 가능한 연결 도구·브라우저로 수행합니다. 도구의 실제 승인 거절은 우회하지 않습니다.

## 실행 범위와 증거

실행은 작업 사본의 `workspace-write` 범위를 유지하고, ChatGPT 로그인·OpenAI 공급자를 명시합니다. API 키 환경변수는 사용하지 않으며 유료 API로 자동 전환하지 않습니다. 사용자 설정을 읽어도 앱이 정한 작업 범위와 프로젝트별 명령 네트워크 설정은 CLI 옵션으로 적용합니다. 기존 관리 정책·명시적 거절 규칙·서비스 권한을 무시하는 옵션은 추가하지 않았습니다. 도구 사용 중 승인이나 정책 차단이 발생하면 차단 상태로 남고 해당 관리·연결 환경 확인이 필요합니다.

업무 대화에는 직무별 파일 제작·명령 실행 외에 실제 웹 검색과 MCP 호출을 표시합니다. 실행 증거에는 `environment`, `commands`, `external_tools`, `changes`를 저장합니다. MCP 인자·토큰·전체 응답은 증거 목록에 넣지 않습니다. 원본 프로젝트 반영과 게시·배포의 성공 여부는 별도로 확인합니다.
