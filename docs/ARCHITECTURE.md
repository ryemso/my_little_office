## v0.6 현재 실행 구조

Streamlit 로컬 앱(`streamlit_app.py`)이 UI와 Python 서버를 같은 PC 출처에서 제공합니다. `office/store.py`의 SQLite 대기열과 근무 기록, `office/engine.py`의 독립 작업 스레드·Codex CLI 어댑터, `office/component`의 기존 픽셀 사무실 양방향 컴포넌트를 연결했습니다. `office/sync.py`는 사용자가 공개 동의 후 요청한 종료 기록만 GitHub에 저장합니다. UI 새로고침은 작업을 재실행하지 않습니다.

Pages는 공개 화면과 로컬 앱 링크를 제공합니다. Pages → localhost API 직접 호출·페어링은 구현하지 않았으며 설계의 로컬 동일 출처 대체 경로를 기본으로 채택했습니다. 현재 실행 모드는 초안입니다. 프로젝트 파일 수정·테스트 권한은 아직 없습니다. 이전 v0.5 Actions 접수 실행기는 호환용으로 남겼고 새 앱과 동시 실행을 잠금으로 방지합니다. 현재 설치 방법은 [AI_SETUP.md](AI_SETUP.md)를 따릅니다. 아래는 이전 설계 기록입니다.

## v0.5 현재 상태 (2026-10-21)

API 기반 Actions 실행을 로컬 Codex 출근 실행기로 교체했습니다. Actions는 공개 동의가 있는 업무를 대기열에 넣고, PC 실행기가 순차 처리해 검토용 초안을 저장합니다. 인증 정보는 PC에만 유지합니다. 한국 날짜 기준 5시간 구간 2회, 작업당 20분, 오류 시 중단, 체크포인트 복구를 적용했습니다. 실제 구독 로그인 실행은 사용자 PC에서 확인해야 합니다. 제품 작업공간 연결과 실시간 온라인 감지는 다음 단계입니다. 자세한 운영 방식은 [AI_SETUP.md](AI_SETUP.md)를 따릅니다. 아래 이전 기록의 API 설정은 과거 설계입니다.

# 시스템 설계
## 현재
GitHub: 설계·코드·결정·비식별 작업 기록의 기준 저장소.
GitHub Actions: 정적 파일 검사·Pages 배포.
GitHub Pages: 회사와 직무를 살펴보는 공개 사무실 화면.
AI 초안은 GitHub 인증 후 Actions에서 수동 실행하고 공개 JSON으로 기록한다. API 키와 모델 설정이 필요하다. 사무실 직접 실행 API·비공개 업무 DB·생성 코드 실행은 미연결이다. 상세: [AI 설정](AI_SETUP.md).

## 이후 연결
공개 화면 → 인증된 API → 권한 검사 → 업무 DB·대기열 → 실행기 → 결과물·검토.
작업 실행은 사용자 세션에 종속되지 않는 서버에서 처리한다. 브라우저에 비밀 키를 두지 않는다.
공개 소개와 실제 내부 업무를 분리한다. 내부 업무·승인·지출·고객 자료는 인증된 API로 제한하고 공개 JSON에 담지 않는다.

## 데이터 모델 초안
- Project: id, 목표, 범위, 자원, 예산, 검증·중단 기준
- Task: id, project_id, 목표, 입력, 담당, 검토자, 상태, 선행 작업, 완료 기준, 결과물 참조
- Run: id, task_id, 실행기, 시작·종료, 상태, 실제 비용, 마지막 신호
- Artifact: id, task_id, 저장 위치, 버전, 공개 범위, 검증 상태
- Approval: 대상 작업·버전, 구체 행동, 영향, 요청·결정 시각, 결정자, 만료
- Decision: 선택, 근거, 대안, 변경 이유
- Metric: 지표 정의, 기간, 원천, 측정값, 데이터 품질
실행 로그·거래 증거를 공개 저장소에 원문 저장하지 않는다.
