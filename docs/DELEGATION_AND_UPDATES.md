# 총괄 자동 배정과 업데이트 후 실행 (v0.7)

## 대표가 한 번 지시하는 흐름

출근 → 총괄 선택 → **총괄에게 지시하면 하부 직원에게 자동 배정** 체크 → 목표 입력 → 업무 지시.

총괄이 1~6개 업무를 배정하고 직원들이 순서대로 처리합니다. 앞 직원의 결과는 다음 직원에게 전달됩니다. 마지막에 총괄이 전체 제출물을 검토하고 최종 결과·남은 문제를 보고합니다. 대표의 원래 업무 카드가 **검토 대기**로 바뀌면 최종 보고를 읽고 완료 처리합니다.

예: “모바일 사용자용 기능을 기획하고 코드 초안을 작성한 뒤 검토해줘” → 총괄 계획 → 기획 → 개발 → 총괄 보고. 실제 배정 직무와 수는 총괄의 결과에 따라 달라집니다.

이 기능은 현재 직원들의 **문서·코드 초안 작업을 자동으로 이어주는 기능**입니다. 제품 파일 수정·테스트 실행·배포는 아직 연결하지 않았습니다. 실제로 실행하지 않은 기능 개발을 완료했다고 표시하지 않습니다.

## 구현 설계

- 기존 SQLite 업무 테이블을 데이터 삭제 없이 확장합니다. `kind`는 단독 업무·총괄 계획·직원 업무·최종 보고를 구분하고, `root_id`와 `ordinal`로 회사 지시와 수행 순서를 연결합니다. `plan_json`은 최초 배정 계획을 보존합니다.
- 계획은 역할·지시만 가진 JSON으로 검증합니다. 총괄 자신에게 재배정하거나 6개 초과 업무를 만들 수 없습니다. 형식이 틀리면 직원 업무를 실행하지 않고 실패로 제출합니다.
- 한 지시의 호출 수는 계획 1회 + 직원 최대 6회 + 보고 1회, 최대 8회입니다. 자동 재계획·재귀 배정·반복 수정 루프는 없습니다.
- 직원은 앞 직원이 결과를 제출한 뒤 실행합니다. 직원이 여러 명이어도 실제 Codex 프로세스는 한 번에 하나만 실행합니다.
- 업무 완료와 하부 업무 생성은 동일 DB 트랜잭션입니다. 같은 응답을 다시 처리해도 직원·보고 업무를 중복 생성하지 않습니다.
- 하부 작업이 실패·취소·중단되면 대표 업무를 ‘팀 업무 중단’으로 표시하고 남은 배정을 취소합니다. 사용 한도 오류는 출근 상태도 멈춥니다. 대표는 완료된 결과를 읽고 추가 지시로 새 계획을 요청합니다.
- 직원 사이의 대기 구간에 앱을 재시작하면 완료된 제출물은 유지하고 남은 배정을 이어갑니다. 실제 직원 실행 중 PC가 종료되면 해당 업무와 팀을 중단으로 복구하고 자동 재실행하지 않습니다.
- 출퇴근은 직접 제어합니다. 일일 근무 시간·횟수 제한은 없습니다. 개별 실행 20분 제한과 Codex 자체 사용 한도는 유지합니다.

## 업데이트 후 실행

이번 버전을 **한 번** 받아 프로젝트 폴더에 적용한 뒤부터 `update-office.bat`을 사용합니다.

1. 켜진 사무실의 실행 터미널을 종료합니다. 브라우저 창만 닫으면 서버가 계속 실행 중일 수 있습니다.
2. 프로젝트 폴더의 `update-office.bat`을 더블클릭합니다.
3. 최신 GitHub 코드를 확인·적용한 뒤 `start-office.bat`으로 사무실을 엽니다.

매번 ZIP을 찾아서 압축 풀 필요는 없습니다. 업데이트가 필요 없는 날에는 기존 `start-office.bat`으로 바로 실행합니다. 처음 이 기능을 받기 위한 최신 ZIP 다운로드는 한 번 필요합니다.

## 업데이트가 보존하는 것

- `.venv`를 새로 덮어쓰지 않습니다. 의존성 목록이 바뀌면 기존 환경에 필요한 패키지를 설치합니다.
- PC의 MyLittleOffice 업무 DB·로그·Codex 로그인 정보는 다운로드·교체 대상으로 포함하지 않습니다.
- 공개 실행 기록 `site/data/tasks.json`도 코드 배포 목록에서 제외합니다.
- 코드에 직접 수정한 내용이 있거나 같은 이름의 사용자 파일이 있으면 업데이트를 중단합니다. 임의로 덮어쓰지 않습니다.
- 변경 전 관리 파일을 `.office-backups`에 저장하고, 파일 교체·구문 검증·의존성 설치 실패 시 이전 코드를 복구합니다. 설치된 패키지 자체를 과거 버전으로 완전히 되돌리는 기능은 없으므로 의존성 오류는 install-office.bat으로 확인·복구해야 합니다.
- 파일 교체 도중 PC가 꺼지면 다음 업데이트 시 저널과 백업으로 이전 파일을 복구한 뒤 재시도합니다.
- 실행 중인 직원과 같은 프로세스 잠금을 사용해 작업 도중 코드 교체를 막습니다.

`office-release.json`은 배포 대상 코드·문서와 SHA-256 해시 목록입니다. 고정한 GitHub 커밋의 ZIP을 내려받아 이 목록에 있는 파일만 검증하고 적용합니다. 경로 탈출·심볼릭 링크·크기 제한을 검사합니다. 이 파일은 코드 업데이트 확인용이며 ChatGPT 인증 파일이 아닙니다.

네트워크 오류·GitHub 요청 제한이면 업데이트는 중단됩니다. 현재 버전으로 실행하려면 `start-office.bat`을 사용합니다. Git 설치는 필요하지 않습니다. git checkout에서 관리 파일을 업데이트하면 git에는 로컬 변경으로 보일 수 있으므로 git pull과 혼용할 때 변경 상태를 먼저 확인하세요.

## 개발자가 변경 후 실행할 검사

```bash
python scripts/build_office_component.py
python scripts/build_release_manifest.py
python scripts/build_release_manifest.py --check
python -m unittest discover -s scripts/tests -v
node scripts/check_office_component.cjs
node --check site/app.js
python scripts/check_site.py
```

현재 36개 테스트로 배정·실패·취소·재시작·DB 이전·화면 조작·업데이트 검증·복구를 확인합니다. Codex 응답은 모의 응답이며 실제 구독 로그인·모델의 계획 생성 품질·Windows 배치 실행·실제 네트워크 다운로드는 사용자 PC에서 최종 확인해야 합니다.
