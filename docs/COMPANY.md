# 회사 및 운영 설계
## 확정된 방향
대표는 사용자, 총괄은 지시를 업무로 구체화하고 결과를 검토하는 역할이다. 사업은 게임에 한정하지 않으며 제품·웹 기능·업무 자동화·데이터 서비스·디지털 상품을 포함한다. 처음에는 사업 하나로 업무 운영을 검증한다.

## 목표와 성과
실제 고객에게 유용한 결과물을 제공하고 수익 가능성을 실험한다. 수익 보장은 하지 않는다.
- 업무: 완료 결과물, 검수 결과, 재작업
- 고객: 실제 방문·사용·문의·구매·재방문
- 재무: 증빙이 있는 매출·비용·환불·순이익
시뮬레이션 값은 실제 지표와 분리하고, 측정하지 않은 값은 0이 아닌 미측정으로 표시한다.

## 공통 업무 계약
업무마다 목표, 배경, 입력 자료, 실행 담당 한 명, 검토 담당, 결과물, 완료 기준, 제한, 선행 업무, 진행 기록, 증거를 지정한다.
상태: 할 일 → 진행 중 → 검토 중 → 필요한 경우 승인 대기 → 완료.
보조 상태: 막힘, 실패, 취소. 검수 실패는 진행 중으로 돌린다. 완료에는 파일·코드·테스트·게시 주소 등 증거가 필요하다.
실행 중 표시는 실제 실행기 신호가 있을 때만 사용한다.

## 협업
책임자는 한 명이다. 인계 시 결론·근거·미해결 사항·결과물 위치를 전달한다. 기본 검토는 2회 이내, 이후 총괄에게 이관한다. 실행 횟수·시간·비용을 제한한다. 막힘에는 필요한 정보와 해제 조건을 기록한다.

## 권한
조사, 초안, 코드 작성, 테스트, 승인 범위 내 수정은 자율 진행한다.
지출·계약·금융 거래·민감한 권한 변경 등은 실제 도구의 정책과 대표 승인을 따른다. 외부 메시지 발송은 명시적 지시가 있는 범위에서만 수행한다. 승인함에 대상·행동·금액·공개 정보·영향·유효기간을 표시한다. 승인 후 내용이 바뀌면 기존 승인을 재사용하지 않는다.
비밀번호·인증은 안전한 사용자 입력 절차로 처리한다.

## 지속 운영의 경계
채팅 화면만으로 대화 종료 이후 계속 실행되지 않는다. 지속 운영은 실행 서버·대기열·예약 작업 연결 이후 가능하다. 초기 화면은 설계 탐색용이다.
