# AI 업무 실행 연결 v0.4

## 현재 구현
GitHub Pages 사무실 → 공개용 업무 지시 작성·복사 → GitHub Actions의 `AI office task` 수동 실행 → 직무별 OpenAI Responses API 호출 → 결과·사용 토큰을 `site/data/tasks.json`에 기록 → 사무실이 읽어 직원 상태와 결과 표시.
업무 요청은 GitHub 쓰기 권한을 가진 사용자가 GitHub 인증 후 실행한다. Pages에는 실행 토큰이나 API 키를 넣지 않는다. 누구나 볼 수 있는 공개 사무실이므로 실행 지시·결과에 개인정보·고객 자료·비밀번호를 넣지 않는다.

## 최초 설정 — 사용자 입력 필요
1. 저장소 Settings → Secrets and variables → Actions → Secrets에서 `OPENAI_API_KEY`를 등록한다. **채팅·코드·브라우저 사무실에 키를 입력하지 않는다.**
2. 같은 설정의 Variables에서 `OPENAI_MODEL`을 등록한다. 자신의 API 프로젝트에서 접근 가능한 Responses API 모델 ID를 입력한다. 모델을 임의로 고정하지 않는다.
3. API 프로젝트의 결제·사용 한도와 모델 접근을 확인한다. ChatGPT 구독을 실행 자격으로 가정하지 않는다.
4. 공개 가능한 업무를 준비한다. Actions → AI office task → Run workflow에서 `role`, `prompt`, 공개 동의 `publish_consent`를 지정해 실행한다.
5. 첫 검증 업무 예: `plan` / “소규모 업무 자동화 도구의 고객 문제와 검증 지표를 가정과 함께 작성해줘”. 실제 API 사용 비용이 발생할 수 있다.
6. 사무실의 AI 업무 기록에 결과와 토큰·실행 증거 링크가 보이는지 확인한다.

## 역할 코드
lead: 총괄 / plan: 기획·사업개발 / dev: 개발 / design: 디자인·콘텐츠 / market: 마케팅·영업 / data: 데이터·운영.
대표는 실행 대상 직원이 아니다. 첫 버전은 선택한 직원 한 명이 업무 초안을 작성한다. 자동 다직무 인계는 후속 작업이다.

## 실행 범위와 제한
- 한 건당 API 호출 1회, 최대 출력 2400토큰, HTTP 대기 120초, 작업 최대 8분. 자동 재시도 없음.
- 동시에 한 실행만 처리하고 진행 중인 작업을 새 요청으로 자동 취소하지 않는다. GitHub 대기열은 영구 업무 큐가 아니므로 대기·취소 여부는 Actions 기록에서 확인한다.
- AI 결과는 초안이다. 성공 응답도 `review`로 저장하며 대표·검토 담당의 확인이 필요하다.
- 개발 담당은 코드 초안을 만들지만 생성 코드 실행·제품 저장소 수정·배포를 수행하지 않는다. 마케팅은 초안을 만들지만 외부 발송·게시를 수행하지 않는다.
- API 키·모델이 없거나 공개 동의가 없으면 요청 전에 중단한다. 키가 없을 때 가짜 결과를 생성하지 않는다.
- 실패·부분 응답은 성공과 구분하고, 원시 API 오류 내용·키는 기록하지 않는다.
- 공개 목록에는 최신 20개를 표시한다. 이전 기록은 Git 이력에 남는다. 삭제해도 과거 커밋에서 사라지는 것은 아니므로 비밀 자료는 절대 입력하지 않는다.
- 시작·결과 기록을 bot 커밋으로 남긴다. 사무실은 main의 JSON을 직접 읽어 Pages 재배포 없이 갱신한다. 캐시·통신으로 상태 반영이 지연될 수 있다.
- 취소·타임아웃 때 마지막 JSON이 running이면 Actions 실행 상태를 보조 확인해 중단 상태로 표시한다.

## 현재 검증 상태
실제 API 키가 제공되지 않아 유료 호출은 수행하지 않았다. 모의 전송을 사용해 키·공개 동의 누락 차단, 출력 제한, 결과 저장, 실패·부분 응답, 비밀 값 유출 차단을 검증했다. 실제 호출·모델 접근·결제 검증은 사용자 설정 후 남아 있다.
