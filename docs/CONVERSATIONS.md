# 업무 대화방 (v0.10)

실행 터미널을 종료하고 `update-office.bat`으로 업데이트하세요. 업무를 접수하면 **업무 대화**에 대표와 각 직무 이름·아이콘·한국 시각을 붙여 기록합니다. 대화방 선택으로 업무를 전환하며 최근 200개 메시지와 **이전 대화 200개 더 보기**를 제공합니다. 스크롤 영역은 새 메시지에 맞춰 이동합니다.

## 대화 흐름

대표의 업무 지시 → 담당자 접수 → 총괄 계획 시작 → 직원별 업무 배정 → 담당 직원 시작 → 실제 명령 시작·종료 코드 및 공개 진행 메시지 → 직원 결과 → 총괄 최종 검토·보고 순서로 기록합니다. 실패·중단 요청·승인·검토 완료·재시작 복구도 같은 대화방에 남습니다. 연결 작업은 실제 작업 이름과 대상을 표시합니다.

직원이 실제로 내보낸 공개 메시지와 실행 이벤트를 표시합니다. 모델 내부 추론이나 임의로 만든 진행률을 표시하지 않습니다. 공개 진행 메시지가 없는 구간은 시작 상태와 다음 실행 이벤트 사이에 새 메시지가 없을 수 있습니다. 명령의 전체 원문 로그는 PC 로그 폴더에 있고, 대화에는 명령·종료 상태와 최종 결과를 남깁니다. 화면은 2초마다 갱신하며 모델 호출이나 업무 재접수 없이 저장된 기록을 읽습니다.

## 이어서 지시하기

대화 하단 **이 대화에 추가 업무 지시**로 후속 업무를 접수합니다. 화면의 **담당 직원** 선택을 사용하고 총괄이면 자동 배정합니다. 앞 업무의 첨부 자료와 같은 프로젝트를 유지하고 최근 대화를 후속 직원에게 전달합니다. 이전 직원 업무에 대한 추가 지시도 원래 대화방에 연결합니다. 파일·링크가 추가로 필요하면 위 업무 입력란에서 상세 관리의 **추가 지시 / 다시 진행**을 선택해 첨부합니다. 출근한 상태에서 접수해야 합니다.

승인·중단·원본 반영·결과 ZIP·검토 완료는 접힌 **업무 상세 관리**에서 사용할 수 있습니다. 대화는 작업 로그를 보기 쉽게 모으는 화면이며 기존 실행 권한이나 검토 절차를 바꾸지 않습니다. 대화 기록 다운로드는 해당 업무방 전체 JSON을 제공합니다.

## 보존과 이전 기록

SQLite의 `messages`에 업무 상태 변경과 같은 트랜잭션으로 기록합니다. 실행 중 공개 메시지·명령 이벤트는 JSONL을 읽어 별도로 저장합니다. 업무 ID와 이벤트 키로 중복을 방지하고, 총괄·직원·후속 업무를 원래 업무방에 연결합니다. 부분적으로 쓰인 JSONL은 다음 읽기까지 기다립니다. 실행기 종료 직전 아직 저장되지 않은 이벤트는 누락될 수 있으며, PC 재시작 시 실행 중이던 업무는 중단으로 기록합니다.

기존 DB는 보존하면서 저장된 지시·배정·결과·오류를 한 번 가져오고 **기존 기록에서 복원**으로 표시합니다. 과거에 저장되지 않은 진행 과정이나 정확한 실행 시각을 만들어 채우지 않습니다. 복원 시각은 기존 업무의 생성·수정 시각 기준입니다. 재시작해도 복원 메시지를 중복 생성하지 않습니다.

대화 원본은 PC에 저장하며 공개 GitHub 동기화에 메시지 테이블을 추가하지 않습니다. 기존 종료 기록 공개 기능을 선택하면 업무 지시·결과가 공개될 수 있으므로 해당 공개 범위를 확인하세요. 키·토큰 패턴은 실시간 Codex 진단·진행 표시에서 마스킹하지만 대화는 개인정보 제거 도구가 아닙니다.
