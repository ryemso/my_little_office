# 직무별 설계 v0.1
| 역할 | 입력 | 책임 | 결과물·완료 기준 |
|---|---|---|---|
| 대표 | 제안·검토 결과 | 목표·예산·사업 선택 | 결정과 이유 기록 |
| 총괄 | 대표 지시 | 문제 구체화·배정·의존 관계·결과 검토 | 담당·기한·증거·완료 기준이 있는 실행 계획 |
| 기획·사업개발 | 고객 문제·자원·조사 | 고객·가치·상품·가격 가설 정의 | 요구사항과 가설별 검증·중단 기준 |
| 개발 | 승인된 요구사항 | 여러 제품·기능 구현·유지보수 | 작동 코드·의미 있는 테스트·사용 안내 |
| 디자인·콘텐츠 | 고객·브랜드·명세 | 화면·시각 자료·사용 설명 | 실제 화면과 맞는 자산·접근성 확인 |
| 마케팅·영업 | 상품·고객·가치 제안 | 고객 접점 조사·판매 실험 준비 | 근거 있는 문안·채널 계획·측정 지표 |
| 데이터·운영 | 업무·사용·거래 기록 | 지표·데이터 검증·비용·문의 관리 | 정의·원천·누락·한계를 설명하는 보고 |

## 총괄
자원과 제약 확인 → 고객 문제·사업 대안 → 기간·비용·검증 비교 → 업무 분리 → 결과 종합.
완료 보고만 믿지 않고 증거를 확인한다. 막힘을 숨기거나 실제 매출 없이 성과를 꾸미지 않는다.

## 개발
게임, 웹사이트, 앱, 유료 도구, 반복 업무 자동화, 데이터 처리, API·DB·로그인·결제 연동, 관리자 도구, 대시보드를 담당한다.
요구사항 확인 → 영향·의존성 검토 → 변경 구현 → 테스트 → 검토 인계.
비밀 키는 프런트에 넣지 않는다. 실행·배포·외부 연동 권한은 역할별로 제한한다.
결제 기능 제작과 실제 금융 거래 수행은 구분한다.

## 검수
작성자 자체 확인 이후 다른 담당이 요구사항·오류·증거를 검토한다.
작은 변경은 필요한 수준으로 검수하되 같은 내용을 무한 반복하지 않는다.
직무는 논리적 역할이며 아직 별도 실행 에이전트가 아니다.
