# 실제 업무 실행 (v0.8)

회사는 특정 업종이나 초안 작성에 한정하지 않습니다. 기획·개발·수정·문서·디자인·데이터 분석·테스트·홍보·배포를 업무로 다룹니다. 실행할 파일과 프로그램, 서비스 계정의 연결 상태에 따라 실제로 수행합니다.

## 바로 시작

업데이트 후 출근하고 **업무 프로젝트**에서 **회사 작업실**을 선택합니다. “작은 웹 도구를 만들고 파일로 저장한 뒤 테스트해줘”, “소개 페이지와 홍보물을 제작해줘”처럼 지시합니다. 총괄 자동 배정을 켜면 직원들이 같은 작업 폴더를 이어서 사용합니다.

회사 작업실은 기본 생성됩니다. 직원들은 결과를 문장으로만 답하지 않고 실제 파일로 만듭니다. 새 작업은 독립된 작업 폴더에서 진행하며, 결과 카드에 변경 파일·실행 명령·종료 코드·파일 차이·결과 ZIP을 표시합니다.

## 기존 프로젝트 연결

**프로젝트·배포·홍보 연결 관리**에서 프로젝트 이름과 PC 폴더를 등록한 뒤 업무 지시의 프로젝트로 선택합니다. 개별 프로젝트 폴더를 지정하세요. 홈·시스템·사무실 상태 폴더 전체는 등록하지 않습니다.

작업 시작 당시의 코드와 자료를 작업 사본으로 가져옵니다. 원본의 미커밋 변경도 현재 내용으로 가져오며 원본을 바로 덮어쓰지 않습니다. 총괄 계획과 최종 검토는 읽기 전용, 직원 업무는 프로젝트 작업 사본의 파일 작성·수정·명령 실행 권한으로 동작합니다. 역할명에 따른 초안 제한은 없습니다.

패키지 설치나 외부 자료가 필요하면 해당 프로젝트의 네트워크 설정을 켭니다. 기본 회사 작업실은 네트워크 사용이 켜져 있습니다. Codex 자체의 정책·실행 권한·사용 한도는 그대로 적용되며 실패 시 더 넓은 시스템 권한으로 자동 전환하지 않습니다.

## 테스트와 원본 반영

직원이 실행한 명령과 실제 종료 코드를 기록합니다. 마지막 테스트·빌드 명령의 실패가 확인되면 업무를 실패로 표시해 후속 배포로 넘어가지 않습니다. 실행 기록이 없으면 테스트를 통과했다고 간주하지 않습니다. 모든 테스트 프레임워크의 의미를 자동 판별하는 장치는 아니므로 결과와 로그를 함께 확인합니다.

작업 결과를 확인한 뒤 퇴근하고 **변경 파일을 원본에 반영**을 누릅니다. 작업 이후 사용자가 원본의 같은 파일을 수정했다면 충돌로 중단합니다. 반영 전 파일은 작업 폴더 옆에 백업합니다. 실행 중인 사무실 자체 코드를 반영했다면 앱을 재시작합니다. 결과 ZIP은 원본 반영 전에도 받을 수 있습니다.

파일 반영의 오류는 백업으로 되돌리지만 다중 파일 교체 도중 PC 전원이 끊기는 상황까지 원자적으로 보장하지는 않습니다. 반영 백업과 작업 사본을 보존해 복구할 수 있습니다.

## 배포·홍보·기타 외부 실행

외부 서비스는 실제 계정과 실행 방법이 있어야 동작합니다. 해당 서비스의 CLI·프로젝트 스크립트를 PC에서 준비하고 로그인한 다음 **실행 작업 연결**에 다음을 등록합니다.

- 프로젝트와 작업 이름.
- 실제 게시·배포 대상: 계정·채널·서비스·환경을 구분할 수 있는 이름.
- 실행 인자 JSON 배열. 예: `["npm", "run", "deploy:preview"]`, `["python", "scripts/publish_campaign.py"]`.
- 자동 실행 허용 여부.

예시 스크립트나 npm 명령은 해당 프로젝트에 실제로 있어야 합니다. 이름을 입력하는 것만으로 외부 서비스 연동이 생성되지는 않습니다. 명령이나 인자에 비밀 키를 넣지 말고 서비스의 공식 로컬 로그인·환경 설정을 사용하세요.

등록 명령을 배정하는 action 필드에는 실제 등록된 작업 ID만 사용할 수 있습니다. 모델이 만든 임의 명령을 외부 실행 연결로 등록하지 않습니다. 연결된 작업은 등록 당시 명령·대상 설정을 업무에 저장합니다.

자동 실행을 허용하면 총괄 배정 후 바로 실행합니다. 허용하지 않은 작업은 **게시·배포 승인 대기**에서 실제 명령·대상·앞 직원의 결과를 확인한 뒤 승인합니다. 승인 이후 작업 파일이 바뀌면 실행을 중단합니다. 등록 명령이 프로젝트 스크립트를 실행하는 경우 직원이 수정한 스크립트도 실행되므로, 자동 실행 권한은 이 범위를 포함합니다.

외부 명령은 Codex 파일 샌드박스 안의 추론 도구가 아니라 소유자가 연결한 PC 프로그램으로 실행됩니다. 대상 서비스의 계정 권한을 사용합니다. 중단하더라도 이미 게시·배포된 외부 결과를 되돌리는 것은 별도의 서비스 작업입니다. 종료 코드와 출력은 실행 증거이며 실제 공개 주소·게시 상태는 서비스 응답으로 확인합니다.

등록된 작업이 없어도 사용자가 대상·내용·행위를 승인했고 연결 도구나 브라우저가 사용 가능하면 일반 직원 업무로 실행할 수 있습니다. 로그인은 게시 승인을 대신하지 않으며 도구 자체의 승인 절차·거절을 우회하지 않습니다. 로그인 요청은 대기 후 재개하고, 게시물 재열람으로 완료를 확인합니다. 기존 지시가 등록 작업만 사용하도록 제한했다면 같은 업무방에서 그 제한을 변경하는 후속 지시가 필요합니다. 모든 SNS·호스팅 서비스의 전용 커넥터가 이미 내장된 상태는 아닙니다. 필요 서비스의 전용 설정 UI는 이 구조에 추가할 수 있습니다.

## 저장과 범위

- 프로젝트 등록·연결 작업·실행 증거는 PC DB에 저장합니다.
- 같은 총괄 지시의 직원들은 한 작업 사본을 공유합니다. 별개 지시는 서로 다른 작업 사본입니다.
- 원본 복사에서 `.git`, `.venv`, `node_modules`, `.env*`, 주요 인증 설정과 심볼릭 링크는 제외합니다. 모든 종류의 비밀 정보를 자동 식별한다는 뜻은 아닙니다. 프로젝트와 제공 자료를 직접 선택하세요.
- 대형 폴더를 실수로 복사하지 않도록 현재 작업 사본은 50MB·10,000개 파일 범위입니다. 실행당 20분과 자동 배정 최대 6개는 운영상 보호 장치이며 직무나 사업 분야 제한과는 다릅니다.
- 실행 기록과 작업 파일이 없는데 외부 활동·매출·테스트 성공을 만들어 표시하지 않습니다.
