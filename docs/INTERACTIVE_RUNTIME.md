# 실행 중 사용자 확인 · v0.19

## 적용과 사용

사무실을 종료하고 update-office.bat을 실행한 뒤 다시 출근합니다. 기존 업무 DB·프로젝트·네이버 연결은 유지됩니다.

**직원 실행기·실행 중 승인**을 펼쳐 **실행기 연결 진단**을 누르세요. 설치된 CLI 버전, 실제 app-server 초기화, 생성한 프로토콜 스키마의 지원 여부를 확인합니다. 비밀번호·세션 파일·Codex 설정 전체를 읽어 보고하지 않습니다. 이 진단은 모델에게 업무를 실행시키지 않으며 브라우저 접근 허용을 확인하는 검사도 아닙니다.

현재 검증한 CLI는 **0.163.0**입니다. 다른 버전이면 대화형 전환을 차단합니다. 지원 버전에서 진단을 통과한 뒤 **대화형 시험 모드 사용 · 사용자 승인 요청 수신**을 선택하면 새 업무부터 적용됩니다. 실행 중에는 모드를 바꿀 수 없습니다. 문제가 있으면 업무 중단 후 **기존 실행기로 복귀**할 수 있습니다. 실제 PC의 브라우저 승인 검증 전이므로 기본 실행기는 기존 exec로 유지합니다.

대화형 업무에서 지원되는 요청이 오면 대표 아바타 느낌표에 건수가 표시됩니다. 대표 승인함에서 대상·요청 이유·명령 또는 질문을 확인하고 이번 요청 허용/거절/중단을 선택합니다. 입력을 전송한 뒤에는 **응답 전송 중 · 실행기 처리 확인 전**이며, 실행기의 해결 통지나 해당 도구의 종료가 확인돼야 요청이 해제됩니다. 공개 게시·배포의 기존 원문 승인은 별개로 유지됩니다.

## 지원 범위

- 명령 및 파일 변경의 일회성 승인.
- MCP의 boolean/enum 확인 양식과 선택형 사용자 질문.
- URL형 MCP 인증 요청: 공식 화면을 열어 직접 인증 후 확인. URL은 살아 있는 프로세스 메모리에만 두며 DB·대화에 저장하지 않습니다. 화면에서 완료를 눌러도 실제 로그인 성공을 의미하지 않습니다.
- 자유 입력·비밀번호·OTP 양식, 알 수 없는 RPC 요청, 세부 파일/네트워크 권한 요청은 자동 승인하지 않고 지원되지 않음으로 중단합니다. 해당 권한 요청의 세밀한 편집 UI는 아직 없습니다.
- Chrome 확장 사이트 권한, AI 도구의 origin 동의, 서비스 로그인, 게시 승인은 각각 별개입니다.

## 대기·거절·중단·재시작

요청 대기 중에는 기존 작업의 실행 잠금을 유지합니다. 뒤 직원·다른 작업은 시작되지 않고 해당 예약도 정지됩니다. 실행 시간 예산은 살아 있는 입력 요청 대기 동안 일시 정지되지만, 확인 대기는 최대 15분입니다. 만료·연결 끊김·앱 재시작은 승인으로 처리하지 않으며 예전 요청 응답을 새 프로세스에 전달하지 않습니다.

거절·취소 응답은 원래 실행기로 전달한 뒤 업무를 중단합니다. 거절된 작업을 다른 직원·브라우저·간접 도구로 재시도시키지 않습니다. 기존 exec 실행에서도 실제 도구 응답에 origin gate 거절이 기록되면 blocked로 처리합니다. 보고서 파일이 생성돼도 그 거절을 실행 성공으로 바꾸지 않습니다. 다만 모든 도구의 비정형 결과를 자동 해석하는 기능은 아니며, 일반 로그인 성공을 독립적으로 증명하는 범용 검증기는 아직 없습니다.

## 진단 결과를 읽는 법

진단 성공은 CLI 버전/스키마/통신 초기화가 맞는다는 뜻입니다. 이번 origin 거절의 직접 원인이 확인됐다는 뜻은 아닙니다.

1. 요청 카드가 뜨고 허용 후 실제 본문 관찰이 성공하면 그 origin에서 승인 연결이 검증된 것입니다.
2. 카드 없이 즉시 origin 거절이 반환되면 도구·호스트·상위 정책이 별도 승인을 처리하거나 차단할 수 있습니다. 앱 승인으로 바꾸지 말고 원본 오류와 호스트 연결 상태를 확인해야 합니다.
3. 외부 인증 화면 조치가 필요한 요청은 그 공식 화면에서 처리합니다. Google OAuth·네이버 로그인과 페이지 접근은 각각 따로 검증합니다.

## 검증·제약

로컬 단위 및 모의 subprocess 검사: 두 요청의 역순 응답, 이중 클릭, 만료, RPC ID 타입, 재시작, 중단·연결 끊김, 질문 답변 검증, 비밀 양식 차단, 예약 정지, 실제 도구 거절의 실패 판정.

실제 Codex 0.163.0 바이너리의 스키마 생성과 stdio 초기화를 모델 호출 없이 확인했습니다. 웹 통합 검사는 가짜 실행기가 보낸 두 요청을 느낌표→카드→응답→작업 계속 흐름으로 검사합니다. Chromium 모형과 실제 사용자 Chrome/Google 계정 검증을 혼동하지 마세요.

사용자 Windows의 실제 Codex 모델 턴, 해당 브라우저 origin의 승인 요청 노출, Google 인증 복귀는 아직 실사용 검증 전입니다. API/도구/계정이 Work와 동일하게 제공되는 것도 보장하지 않습니다. 따라서 재설계 D1~D3의 승인 왕복을 구현한 것이며 D0 직접 원인 확정·D4 실제 모델 승인·D5 실제 브라우저 인수·D6 서비스 인수 전체 완료는 아닙니다.
