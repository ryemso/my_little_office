# 직원 활동·업무 일지·외부 상태 연결

## 참고한 기능

참고 저장소: https://github.com/IISweetHeartII/log8-office

README, `backend/app.py`, `backend/memo_utils.py`, `office-agent-push.py`, `docs/AGENT-INTEGRATION.md`를 확인했습니다. 이 저장소는 에이전트 **활동 상태를 표시하는 대시보드**이며 자체적으로 직원의 업무 수행 능력을 제공하는 실행 엔진은 아닙니다.

우리 사무실에는 아래 기능 개념을 독립적으로 구현했습니다. 참고 프로젝트의 소스 코드·고양이·테마·이미지·폰트는 가져오지 않았습니다. 기존 픽셀 캐릭터와 사무실 디자인을 유지합니다.

| 참고 기능 | 우리 사무실 반영 |
|---|---|
| 작업 상태 구분·별칭 정규화 | 대기·회의/계획·작성·조사·명령 실행·외부 연동·오류 |
| 활동에 따른 공간 이동 | 기존 캐릭터가 계획 시 회의실, 검색 시 자료 구역, 그 외 자기 자리로 이동 |
| 상태 푸시와 연결 만료 | 내부 실행기 하트비트, 외부 에이전트 상태 수신, 오래된 연결 표시 |
| 외부 에이전트 초대 | 에이전트별 상태 전용 키 발급·폐기와 로컬 HTTP API |
| 어제 메모 | 한국 날짜별 업무·대화 건수·오류·제출 기록, 업무방 이동, 일지 다운로드 |

## 상태와 완료의 차이

내부 활동은 Codex 명령·검색·MCP·공개 응답 이벤트로부터 기록합니다. 의도나 비공개 추론을 추측하지 않습니다. 예를 들어 ‘작성’은 공개 응답 이벤트이며 실제 파일 저장 성공을 의미하지 않습니다. 명령 실패는 오류 활동으로 표시하고 후속 복구 이벤트를 기다립니다.

하트비트는 앱의 실행기가 살아 있다는 신호입니다. 모델의 진척이나 작업 성공을 증명하지 않습니다. 실행기 신호가 45초 이상 없으면 ‘응답 지연’으로 표시하고 작업을 완료·대기 상태로 바꾸지 않습니다. 아바타 이동도 업무 완료 증거가 아닙니다.

날짜별 일지는 해당 한국 날짜에 마지막 변경된 대표 업무의 **현재** 기록입니다. 과거 시점의 상태를 복원한 감사 장부는 아닙니다. PC의 업무 내용은 공개 Pages에 자동 전송하지 않습니다.

## 외부 도구의 상태 표시

1. 사무실의 **외부 에이전트 상태 연결**에서 로컬 연결 서버를 시작합니다. 기본 주소는 `http://127.0.0.1:8787`입니다. 자동 시작하거나 인터넷에 공개하지 않습니다.
2. 표시 이름을 입력해 상태 전용 키를 발급합니다. 키는 화면에서 확인 후 닫을 수 있으며 DB에는 원문 대신 해시만 저장합니다.
3. 같은 PC에서 외부 프로그램의 환경변수 `OFFICE_AGENT_KEY`에 해당 키를 설정합니다.
4. 프로젝트 폴더에서 `python -m scripts.push_agent --state researching --once`로 한 번 전송합니다.
5. 계속 연결하려면 `--once`를 빼거나 `--state-file`에 아래 형식의 파일 경로를 지정합니다. 파일은 사용자가 지정한 것만 읽고 15초마다 상태를 전송합니다.

```json
{"state":"researching","detail":"공개 자료 조사 중"}
```

키를 명령 인자·프로젝트 파일에 넣지 마세요. `detail`에는 짧은 상태만 보내며 원문·인증 정보를 넣지 않습니다. 서버는 60초간 상태 수신이 없으면 연결 끊김으로 표시합니다. 종료 후 다시 전송하면 연결이 복구되고, 키를 폐기하면 즉시 거절합니다.

연결된 외부 에이전트는 상태 표에 표시됩니다. 우리 직원의 실행·권한·대화방을 대신하지 않습니다. 이 키로 업무 지시, 코드 실행, 파일 조회, 게시 승인은 할 수 없습니다. Codex 외의 도구에 상태 API를 연결했다고 그 도구의 기능이 Codex에 추가되는 것도 아닙니다.

## API

상태 클라이언트는 `Authorization: Bearer <상태 키>`를 사용합니다. 이 PC의 loopback에서만 지원하며 Origin 헤더를 가진 브라우저 요청은 받지 않습니다.

| 메서드·경로 | 동작 |
|---|---|
| GET `/health` | 내용 없는 서버 생존 확인 |
| GET `/agents` | 인증된 상태 목록, 비밀 키·업무 내용 제외 |
| POST `/join-agent` | 키에 연결된 에이전트의 상태 수신 |
| POST `/agent-push` | `state`, 선택 `detail` 수신 |
| POST `/leave-agent` | 해당 키의 에이전트를 연결 끊김으로 표시 |

상태 입력은 최대 4KB이고 detail은 240자입니다. 한 키는 한 에이전트에 연결됩니다. 표시 이름은 사무실에서 발급할 때 정합니다. 알려지지 않은 상태·추가 필드는 거절합니다. UI에서 키를 폐기할 수 있습니다. 별도 터널·모바일 원격 제어·인터넷 공개는 포함하지 않습니다.
