# 실제 업무 실행·게시·예약

## 처음 한 번 준비

1. 사무실을 종료하고 `update-office.bat`을 실행합니다.
2. 사무실에서 출근하고, 연결 관리의 **로컬 실행·CSV 분석 검증 업무 시작**을 실행합니다. 파일·분석값·실행 기록을 통과해야 합니다.
3. GitHub 반영을 쓰려면 PC에 GitHub CLI를 설치하고 `gh auth login`으로 연결합니다. 연결 관리에 `owner/repository`를 등록합니다.
4. 네이버를 쓰려면 연결 관리에서 **브라우저 실행 준비**를 누릅니다. 완료 후 **네이버 로그인 창 열기**를 눌러 열린 전용 브라우저에서 직접 로그인합니다. 로그인·2단계 인증·CAPTCHA는 본인이 처리합니다. 로그인 성공 시 창이 닫히고 세션은 PC에 남습니다. 평소 Chrome 계정을 복사하거나 비밀번호를 전송하지 않습니다.
5. 블로그 ID와 원문 JSON 경로를 입력하고 **네이버 임시 저장·발행 기능 연결**을 누릅니다. 임시 저장과 발행 두 작업이 등록됩니다.

브라우저 다운로드가 실패하면 연결 관리의 설치 상태와 PC 상태 폴더의 `browser-install.log`를 확인합니다. 로그인 창이 열려 있으면 게시 작업이 같은 세션을 동시에 사용하지 않도록 중단됩니다.

## 대표 지시 예시

> 이 프로젝트 자료와 공개 출처를 조사해서 블로그 글을 만들어줘. 출처 URL과 확인 시각을 자료 파일로 남기고, publishing/naver.json에 고유 post_id, title, body를 작성해. 네이버 임시 저장을 먼저 검증하고 발행 승인을 요청해. 실제 게시물 URL과 원문 검증 결과를 제출해.

게시 파일 형식:

```json
{
  "post_id": "company-article-20261022-01",
  "title": "게시할 제목",
  "body": "첫 문단\n\n두 번째 문단",
  "images": ["publishing/chart.png"]
}
```

`images`는 선택입니다. PC 절대 경로, 프로젝트 밖 파일, 심볼릭 링크는 허용하지 않습니다. 문서의 기본 본문은 일반 텍스트입니다. 복잡한 표·HTML·동영상 삽입은 지원하지 않습니다. 지원 사진은 jpg/jpeg/png/webp/gif이며 개당 20MB, 최대 20개입니다. 사진 업로드 버튼 동작이 바뀌면 작업을 실패로 처리합니다.

## 실행과 완료 판정

- 총괄은 제작 업무에 `artifacts`로 필수 파일을 선언하고 담당자에게 실제 작성을 배정합니다. 비어 있거나 없는 산출물은 제출 성공으로 처리하지 않습니다. 파일 경로·크기·SHA256을 실행 증거에 남깁니다.
- 직원들은 동일한 팀 작업 사본을 사용합니다. 완료한 앞 직원의 파일과 실행 증거를 다음 직원이 이어받습니다.
- 승인함에서 대상과 변경 내용을 확인한 뒤 실행합니다. 승인 후 파일이 바뀌면 다시 승인을 받아야 합니다.
- 네이버는 제목·본문 입력 후 저장된 글을 다시 열어 원문과 비교합니다. 같은 원문을 발행하기 전 임시 저장 검증이 필요합니다.
- 발행 작업은 전체공개·현재 발행으로 처리합니다. 실제 URL을 얻은 다음 새 페이지에서 제목·본문과 이미지 수를 검사합니다. 결과에 게시 URL과 화면 캡처를 남깁니다. 이미지 수 검사는 이미지 자체의 픽셀 동일성 검증이 아닙니다.
- 같은 `post_id`와 같은 원문은 중복 발행하지 않습니다. 같은 ID로 내용을 바꾸면 중단합니다. 다른 글은 반드시 새 ID를 사용합니다.
- GitHub는 `office/` 전용 브랜치에 변경분을 올리고 원격 커밋을 조회합니다. 기본 브랜치 병합과 배포는 별도 작업입니다.

## 실패 복구

대표 느낌표에서 **실패한 단계부터 다시 진행**을 누르면 성공한 앞 단계는 유지하고 실패 단계부터 이어갑니다. 외부 작업 승인은 다시 받습니다. 출근해야 대기열이 실행됩니다.

발행 클릭 후 결과를 잃은 경우 자동 재발행하지 않습니다. 연결 관리의 **네이버 결과 확인 작업 연결**에 기존 게시 URL과 원문 JSON을 지정하고 총괄에게 해당 확인 작업을 실행하도록 지시합니다. 실제 원문이 일치해야 발행 완료 기록을 복구합니다. 임시 저장만 된 것이 확인된 경우 URL을 비우고 같은 기능을 연결해 저장 원문을 다시 검사합니다. 이 검사는 공개 글 존재 여부를 전수 검사하는 기능이 아니므로 불확실하면 먼저 블로그의 실제 게시물을 확인해야 합니다.

원격 변경과 GitHub 작업 사본이 충돌하면 덮어쓰지 않습니다. 최신 저장소를 받은 폴더로 새 업무를 시작합니다. GitHub 일시적인 조회 오류만 최대 두 번 재시도하며 게시·쓰기 요청은 무조건 반복하지 않습니다.

## 예약·반복

**예약·반복 업무**에서 프로젝트·담당자·지시·한국 시간의 첫 시각과 반복 간격을 등록합니다. 0분은 한 번이며 반복은 최소 5분입니다. 예를 들어 1,440분은 하루 간격입니다. 예약에는 글마다 회차가 전달되므로 고유 post_id를 만들도록 지시하세요.

- PC 서버가 켜져 있고 출근 중일 때만 접수합니다. 클라우드에서 PC를 깨우는 기능은 아닙니다.
- PC가 꺼져 놓친 회차는 복귀 후 한 건만 접수합니다. 이미 접수한 회차는 중복 접수하지 않습니다.
- 앞 회차가 진행·승인 대기 중이면 다음 회차를 겹쳐 실행하지 않습니다.
- 앞 회차가 실패하면 반복 예약을 일시 정지합니다. 원인을 확인한 후 예약 재개를 누릅니다.
- 예약 정지는 아직 접수하지 않은 회차에 적용합니다. 접수된 업무는 해당 업무의 중단 버튼으로 취소합니다.
- 예약도 외부 실행 승인 규칙을 유지합니다. 업무 생성과 외부 발행 완료를 구분합니다.

## 검증 범위

단위·회귀 테스트 및 별도의 Chromium 편집기 모형 통합 테스트를 실행합니다. 편집기 모형은 제목·본문 입력, 저장 후 재열람, 발행, URL 원문 검증과 중복 방지를 검사하며 실제 네이버에 게시하지 않습니다. 실제 네이버 화면의 제목·본문 컨테이너, 저장 글 목록과 발행 설정은 읽기 전용으로 확인해 연결했습니다.

사용자 Windows PC에서의 Codex 명령 성공, 전용 브라우저 로그인과 실제 네이버 저장·발행은 별도 실사용 검증이 필요합니다. 네이버 화면 변경·로그인 만료·인증 요구가 있으면 성공으로 표시하지 않고 중단합니다.
